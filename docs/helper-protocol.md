# 헬퍼 프로토콜

> [nas-design.md ADR-3](../nas-design.md) 의 구현 스펙.

## 1. 무엇을 푸는 문제인가

서버는 root로 돌고, 파일 접근은 **요청한 사용자의 권한으로** 일어나야 한다. 그 임퍼소네이션을 애플리케이션이 흉내내지 않고 커널에 맡기기 위해, 사용자별로 강등된 헬퍼 프로세스를 띄우고 유닉스 소켓으로 오퍼레이션을 보낸다.

### 지켜야 하는 불변식

> **서버 프로세스는 경로 기반 syscall 과 `*at()` 계열을 절대 직접 호출하지 않는다.**
> 서버가 만지는 것은 헬퍼가 넘겨준 fd 에 대한 `read`/`write`/`pread`/`pwrite`/`sendfile`/`fstat` 뿐이다.

이 규칙이 왜 절대적인가: **fd 패싱이 옮겨주는 권한 검사는 "그 파일의 read/write" 하나뿐이다.** `openat`·`renameat`·`unlinkat`·`mkdirat` 는 헬퍼가 준 dirfd 를 넘겨도 **호출 프로세스의 자격증명으로 매번 새로 검사**하고, 호출자가 root 면 DAC 를 전부 통과한다. 서버가 이런 호출을 하나라도 하면 그 경로에서는 권한 검사가 사라진다.

그래서 **네임스페이스를 건드리는 모든 연산은 오퍼레이션으로 존재한다.** 이 프로토콜이 `OPEN` 하나가 아닌 이유가 그것이다.

`internal/wire` 가 의존성 없이 손으로 쓰인 것도 같은 이유다. 이 코드는 보안 경계이므로 감사 가능해야 하고, 생성된 코드 + 런타임보다 읽을 것이 적어야 한다.

## 2. 기동과 수명

```
서버(root) ──setpriv --reuid --regid --init-groups──> darak-helper
                       fd 3 = 소켓(socketpair)
```

- 헬퍼는 **사용자당 1개**. 이건 캐시 크기가 아니라 모델 그 자체다 — 헬퍼가 곧 그 사용자의 자격증명이므로 둘이 공유할 수 없고, 하나가 둘을 가져도 얻는 게 없다. 소켓은 `socketpair(AF_UNIX, SOCK_SEQPACKET)` 로 만들어 자식에게 fd 3 으로 물려준다. 파일시스템에 소켓 경로를 만들지 않으므로 접근 제어를 따로 걱정할 필요가 없다.
- 강등은 `setpriv` 가 아니라 **자식 프로세스의 credential**(`SysProcAttr.Credential`)로 한다. 런타임 의존성이 하나 줄고, fork 와 exec 사이에서 일어나 부모 스레드에 영향이 없으며, **보조 그룹을 명시적 목록으로 넘긴다**. 마지막 항목이 중요하다: 그 집합이 서버가 들고 비교할 수 있는 값이 되기 때문이다.
- `SOCK_SEQPACKET` 을 쓴다. 메시지 경계가 보존되므로 길이 프리픽스 프레이밍의 재조립 코드가 필요 없고, `SCM_RIGHTS` 로 붙인 fd 가 **어느 메시지에 속하는지 모호해지지 않는다**(`SOCK_STREAM` 은 보조 데이터가 스트림 중간에 실려 경계가 흐려질 수 있다).
- 헬퍼는 기동 시 `umask(0)` 을 설정한다. mode 는 항상 요청에 명시된 값을 그대로 쓴다 — umask 는 프로세스 전역 상태라 동시 요청에서 레이스가 나므로, 여기에 기대지 않는다.
- 헬퍼는 기동 시 루트 디렉터리(`/srv/data`)를 열어 **root dirfd** 로 붙들고 있는다. 이후 모든 경로는 이 dirfd 기준 상대 경로다. 이 fd 는 부모에게서 물려받지 않고 **헬퍼가 직접 연다** — root 프로세스가 건네준 fd 는 사용자가 통과한 적 없는 권한 판정을 담고 있기 때문이다.

### 풀이 결정하는 것 (`internal/helperpool`)

- **그룹 변경 시 교체.** 헬퍼는 기동 시점의 보조 그룹을 평생 유지한다. 그래서 팀에 추가해도 교체 전까지 보이지 않고, **더 나쁘게는 팀에서 빼도 접근이 계속 된다.** 풀은 기동 시 넘긴 집합을 기억해 두고 재해석한 값과 비교해 다르면 교체한다. 순서·중복은 이름 서비스 마음이므로 정렬·중복제거 후 비교한다 — 그러지 않으면 아무 이유 없이 재기동한다.
- **자격증명 조회는 TTL 캐시**(기본 30초). 요청마다 NSS 를 왕복하지 않기 위한 것이고, 그 값이 곧 **팀 변경이 반영되기까지의 지연**이다. 그룹 변경은 드물고 요청은 잦다는 판단.
- **유휴 회수**(기본 5분)와 **동시 헬퍼 상한**(기본 64, LRU 축출). 진행 중인 요청이 있는 헬퍼는 절대 종료하지 않는다 — 이미 허용된 작업을 그와 무관한 이유로 끊는 것이기 때문이다.
- 상한에 걸렸고 축출할 유휴 헬퍼가 없으면 **대기가 아니라 실패**한다. 대기시키면 호출자가 자기와 무관한 사용자의 작업을, 기약 없이 기다리게 된다.

## 3. 경로 해석

모든 경로는 root dirfd 기준 상대 경로이며, 커널이 해석한다.

```c
openat2(rootfd, rel, &{ .resolve = RESOLVE_BENEATH | RESOLVE_NO_MAGICLINKS })
```

`RESOLVE_BENEATH` 는 `..`·절대 경로 심볼릭 링크·루트 밖으로 나가는 모든 해석을 **커널이** 거부한다. 문자열 검사를 하지 않는 이유가 이것이다.

### 네임스페이스 연산은 부모 dirfd + basename 으로

`renameat2`·`linkat`·`unlinkat`·`mkdirat` 에는 `openat2` 의 resolve 플래그가 **적용되지 않는다.** 이들에게 `..` 이 든 경로를 그대로 넘기면 루트를 벗어난다.

따라서 이 연산들은 두 단계로 처리한다.

1. 경로를 `dir` + `base` 로 쪼갠다. `base` 가 `""`·`.`·`..` 이거나 `/` 를 포함하면 거부.
2. `dir` 을 `openat2(RESOLVE_BENEATH, O_PATH|O_DIRECTORY)` 로 연 dirfd 를 얻고, 그 dirfd 와 `base` 로 `*at()` 을 호출한다.

`base` 는 단일 컴포넌트이므로 `*at()` 이 해석할 여지가 없고, dirfd 는 이미 커널이 루트 안임을 보장한 것이다.

## 4. 프레이밍

`SOCK_SEQPACKET` 이므로 **1 메시지 = 1 프레임**이다. 길이 프리픽스는 없다.

- 최대 프레임: **64 KiB**. 요청은 경로 몇 개뿐이라 남는다. 디렉터리 목록 응답은 이 한도에 걸릴 수 있으므로 §6 의 이어받기 규약을 쓴다.
- 정수는 전부 **빅엔디언**.
- `string` = `uint16` 길이 + 바이트. `bytes` = `uint32` 길이 + 바이트.

### 요청

| 필드 | 크기 | 비고 |
|---|---|---|
| `id` | u64 | 요청 식별자. 응답에 그대로 실려 온다 |
| `op` | u8 | §5 |
| `flags` | u32 | open flags / rename flags / 옵션 비트 |
| `mode` | u32 | 생성 mode. `umask(0)` 이므로 그대로 적용된다 |
| `path` | string | root dirfd 기준 상대 경로 |
| `path2` | string | `RENAME`/`LINK` 의 목적지 |
| `name` | string | xattr 이름 |
| `value` | bytes | xattr 값 |

### 응답

| 필드 | 크기 | 비고 |
|---|---|---|
| `id` | u64 | 대응하는 요청의 id |
| `errno` | u32 | `0` = 성공. 아니면 그대로 `syscall.Errno` |
| `has` | u8 | 비트 0 = fd 동봉, 비트 1 = stat 포함, 비트 2 = 엔트리 목록 포함 |
| (stat) | 고정 | 아래 |
| (entries) | u32 개수 + 반복 | 이름 + stat |

**fd 는 페이로드가 아니라 `SCM_RIGHTS` 보조 데이터로 온다.** 응답 프레임과 같은 `sendmsg` 에 실린다.

`errno` 는 번역하지 않고 그대로 올린다. `EACCES`/`EPERM`/`ENOENT` 의 구분은 커널의 판단이고, 그것을 앱이 재해석하는 순간 [ADR-1](../nas-design.md) 이 배제한 "앱이 권한을 판단하는 코드"가 다시 생긴다.

## 5. 오퍼레이션

| op | 인자 | 결과 | 비고 |
|---|---|---|---|
| `OPEN` | `path`, `flags`, `mode` | fd | `O_CREAT` 포함. `openat2` 가 직접 해석 |
| `MKDIR` | `path`, `mode` | — | 부모 dirfd + base |
| `UNLINK` | `path` | — | 〃 |
| `RMDIR` | `path` | — | 〃 |
| `RENAME` | `path`, `path2`, `flags` | — | `renameat2`. `RENAME_NOREPLACE` 등 |
| `LINK` | `path`, `path2` | — | 휴지통 규약이 쓴다 |
| `STAT` | `path`, `flags` | stat | `flags` 비트 0 = 심볼릭 링크를 따라가지 않음 |
| `CHMOD` | `path`, `mode` | — | `O_PATH` + `/proc/self/fd/N` |
| `SETXATTR` | `path`, `name`, `value` | — | |
| `READDIR` | `path`, `flags` | 엔트리 목록 | `flags` 비트 1 = 각 엔트리의 stat 포함 |

`FSTAT` 은 없다. 서버는 자기가 들고 있는 fd 에 `fstat` 을 직접 호출할 수 있고, 그것은 fd 연산이므로 불변식을 깨지 않는다.

`READDIR` 이 따로 있는 이유: 서버가 dirfd 를 받아 `getdents` 까지는 할 수 있지만, 각 엔트리의 stat 은 `fstatat(dirfd, name)` 이 되어 **경로 기반 호출**이다. 목록 화면은 항목마다 크기·수정시각이 필요하므로([nas-design §8](../nas-design.md)), 그 조합을 헬퍼 안에서 한 번에 끝낸다. 왕복도 N+1 회에서 1 회로 준다.

## 6. 다중화

요청은 `id` 로 구분되며 **응답 순서는 보장되지 않는다.** 헬퍼는 요청을 받는 즉시 고루틴에 넘기고, 서버는 `id` 로 대기 중인 호출자에게 배달한다.

이게 없으면 head-of-line blocking 이 생긴다 — 큰 업로드 하나가 같은 사용자의 디렉터리 목록 조회를 막는다. 헬퍼가 사용자당 하나뿐이므로 이 문제는 피할 수 없고, 프로토콜 수준에서 풀어야 한다.

`READDIR` 의 응답이 프레임 한도를 넘으면 헬퍼는 잘라서 보내고 `flags` 에 "더 있음" 비트를 세운다. 서버는 마지막 엔트리 이름을 `name` 에 담아 이어서 요청한다.

---

## 7. 이 프로토콜이 하지 않는 것

- **인가 판단.** 전부 커널이 한다. 헬퍼는 경로를 열려고 시도하고 결과를 그대로 돌려줄 뿐이다.
- **경로 정규화.** `RESOLVE_BENEATH` 가 판단한다. 문자열을 손보지 않는다.
- **쓰기 규약.** 임시 파일 → `fsync` → `link` → `rename` 순서는 [nas-design §6](../nas-design.md) 이 정하고 서버가 오퍼레이션을 조합해 구현한다. 헬퍼는 각 단계를 제공할 뿐 순서를 강제하지 않는다.
